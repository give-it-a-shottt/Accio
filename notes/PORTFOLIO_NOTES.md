# 포트폴리오용 기록 — 결정 · 문제 해결

> 나중에 포트폴리오(jsh. 포트폴리오 Accio 사례 · Admin_Docs 트러블슈팅)로 옮길 재료.
> 사실(무엇이 일어났고 어떻게 고쳤는지)만 적는다. 소개 문구 · 면접 답은 옮길 때 사용자와 함께 다듬는다.

## D-1 상품 데이터: 네이버 쇼핑 API → Gemini 가상 상품 (2026-11-04)
- 상황: 검색용 실데이터로 네이버 쇼핑 검색 API를 쓰려 했으나 2026-07-31 종료, NAVER API HUB 이관 대상에서도 빠져 대체 API 없음. 네이버 쇼핑은 robots.txt로 크롤링도 막는다.
- 결정: 카테고리 11 × 키워드 5 × 20개 = 1,100개를 Gemini(gemini-3.5-flash-lite, 구조화 출력)로 생성. 화면에 '데모용 가상 상품' 표시.
- 효과: 실데이터(상품명뿐)보다 설명 · 스펙 · 용도 태그가 풍부해 자연어 검색 효과를 보여 주기 좋고, 시험지 정답을 통제할 수 있다.
- 비용: 무료 등급, 키워드당 1회 호출(55회). 결제 계정 없이 한도 초과 시 과금이 아니라 429.

## D-2 상품 이미지: Pexels → Unsplash → 피그마 AI 생성 (2026-11-04)
- Pexels: 새 API 키 발급 중단. Unsplash: 데모 키 시간당 50회 + 사용 알림 호출 때문에 550장이면 반나절.
- 결정: 피그마 AI(gpt-image-2.5-flare)로 키워드당 3장, 총 165장 생성. 스튜디오 톤 하나로 고정(밝은 웜그레이 배경, 왼쪽 자연광, 글자 · 로고 없음) → 800px webp(합계 약 3.8MB)로 레포에 포함.
- 피그마 정리: 처음엔 캔버스에 가로 한 줄로 늘어져서, 섹션 안에 카테고리 11줄 × 키워드 5 × 3칸 보드로 재배치.
- 크레딧: 1장 약 3(총 약 500).

## T-1 이미지와 상품 설명이 어긋남 (2026-11-04)
- 문제: 키워드당 사진이 여러 장이면 '알루미늄 로우 체어' 사진이 '카키 접이식 의자' 상품에 붙을 수 있다.
- 해결: 사진마다 생김새 설명(scripts/image_subjects.py)을 기록하고, 상품 생성 프롬프트에 함께 넘겨 Gemini가 상품마다 맞는 사진 번호(image)를 고르게 함. 사진당 6~7개로 고르게 분배.
- 추가로 발견: 처음 테스트로 만든 3장은 생김새 설명이 빠져 '무드등 1번(버섯 모양 유리갓)'에 '철제 스탠드' 상품이 붙음 → 실제 생김새를 기록하고 재생성해 해결.

## T-2 생성물에 실존 브랜드 · 상표가 섞임 (2026-11-04)
- 이미지: 무선 이어폰이 특정 실제 제품과 거의 같은 모양, 블록 장난감이 유명 브랜드 브릭처럼 나옴 → 'Generic original design' 프롬프트로 다른 디자인(조약돌형 이어폰, 자석 블록)으로 재생성.
- 브랜드: '바이오더마틱'(실존 '바이오더마' 변형), '한샘디자인', '자연주의' → 프롬프트에 '실존 브랜드를 살짝 바꾼 이름 금지' + REAL_BRANDS 검사로 경고 후 재생성.
- 상품명 · 설명: 고어텍스 · 비브람 · 코듀라 · 맥세이프 · 아이폰 11곳. 원인은 검사가 브랜드 칸만 보고 글은 안 본 것 → 상표 · 기술명 금지 규칙(일반 표현으로: 고어텍스 → 방수 투습 멤브레인) + 상품명 · 설명 · 스펙 전체 검사(TRADEMARKS)로 바꾸고 4개 키워드(상품 + 리뷰) 재생성. 재검사 0건.
- 오탐 처리: '보스'(보스턴), '자라'(자라다)처럼 부분 일치 오탐은 목록에서 빼거나 사람이 판단.

## T-3 생성 결과 품질 검사 자동화 (2026-11-04)
- 생성 스크립트가 키워드마다 출력: 개수(20개 아님), 사진 분배, 브랜드 쏠림(한 브랜드 5개 이상), 상표 경고.
- 1차 생성 55개 키워드 중 9개 경고(개수 부족 3, 브랜드 쏠림 4, 실존 브랜드 2) + 사진 1번이 안 쓰인 1개 → --only 로 해당 키워드만 재생성.

## D-3 리뷰도 생성 (2026-11-04)
- 문제: 목 상세 화면은 모든 상품에 같은 리뷰 3개와 같은 'AI 리뷰 요약'을 붙인다 → 1,100개 상품이 같은 리뷰를 보여 주게 됨.
- 결정: 키워드당 1회 호출로 상품 20개의 리뷰를 4개씩(총 4,401개) 생성. 상품 설명의 아쉬운 점과 상품 평점에 맞춘다. 'AI 리뷰 요약'은 이후 이 리뷰를 실제로 Gemini가 요약(원래 팀 프로젝트의 리뷰 분석 기능 재현).
- 결과: 별점 5점 2,399 · 4점 1,812 · 3점 190(1~2점 없음, 다소 후함). 같은 시작어 반복은 최대 44회(1%).

## S0 키워드 검색 기준점 (2026-11-04)
- LLM 없이 검색어를 띄어쓰기로 나눠 상품명 · 브랜드 · 키워드 · 태그 포함(1점) + 트라이그램 유사도(0.5 가중)로 점수.
- 잘 되는 것: '캠핑 의자', '에어프라이어 대용량', '비 오는 날 신을 운동화'.
- 안 되는 것: '자취방에 둘 저렴한 무드등' → 1위가 화장지(태그 '자취방'에 걸림). P3(Gemini 질의 해석)로 고칠 대표 사례.

## T-4 가격 필터 기본값이 비싼 생성 상품을 숨김 (2026-11-04)
- 문제: 목록 가격 슬라이더 기본값이 0~15만원이고, 필터가 늘 적용돼 15만원이 넘는 생성 상품(최고 89만원, 에어프라이어 · 책상 등)이 검색해도 안 보였다.
- 해결: 슬라이더를 끝까지(최댓값) 두면 상한 없이 보이게 — `high >= PRICE_MAX || price <= high`.

## D-4 생성 상품을 장바구니 · 찜에 담기 (2026-11-04)
- 문제: 장바구니 · 찜 · 최근 본 · 주문은 상품 id 만 저장하고 findProduct(id)로 목 데이터에서 찾는다 → 생성 상품은 못 찾는다.
- 결정: API로 받은 상품 요약을 localStorage(accio:products)에 기억하고 findProduct 가 목 데이터 다음으로 여기를 본다. 화면 7곳을 고치지 않고 한 곳만 바꿈. 한도 1,500개(전체 1,100개보다 크게)라 담아 둔 상품이 지워지지 않는다.

## D-5 생성 상품 상세 화면 (2026-11-04)
- 사진은 고른 1장만(같은 키워드의 다른 사진은 다른 모델이라 섞지 않음), 옵션 없음, 기본 탭은 Gemini가 쓴 '상품 설명'.
- 리뷰: 대표 리뷰 4개 + "데모 상품이라 대표 리뷰 N개만 보여요" 안내. 평점 분포 막대는 4개로 1,240개 분포를 그리면 오해라 숨김. 'AI 리뷰 요약'은 P5 실제 요약까지 숨김.
- '데모 상품' 표시, 함께 보면 좋은 상품은 같은 키워드 인기순(API).
- 실패 처리: 검색 API가 안 되면 목 데이터 검색 + 토스트, 상세는 '불러오지 못했어요 · 다시 시도'. 백엔드를 끈 상태로 확인.

## 운영 메모 추가
- Windows에서 `uvicorn --reload` 를 강제 종료하면 multiprocessing 자식(spawn_main)이 포트 8000을 계속 잡는다(netstat 소유 PID 0). 자식 프로세스를 찾아 종료해야 함 → 개발 중엔 --reload 없이 띄움.

## 운영 메모
- git push 가 가끔 첫 시도에 실패하고 재시도하면 됨(원격 앞선 커밋 없음, 원인 미확인).
- Supabase 키는 새 형식(sb_publishable_ / sb_secret_). 서버는 publishable(읽기), 적재 스크립트만 secret.
